# Alberta Events｜多人自訂尺寸賓果

支援最多 16 人連線的賓果遊戲，可自訂盤面尺寸、查看其他玩家盤面，並以卡牌問答取代選號。卡牌效果目前待定，已可體驗全房同步作答與房主判定流程。

## 啟動

使用 Node.js 22 以上，無第三方套件，不需 `npm install`。前端使用原生 ES modules，請透過伺服器開啟，不要直接開 HTML 檔案。

程式依職責拆分為後端 Domain／Application／Infrastructure／HTTP，以及前端 State／Storage／Network／Views。目錄、物件關係圖及資料流請見 [架構說明](docs/architecture.md)。`server.js` 與 `public/client.js` 僅為啟動入口。

```powershell
npm start
```

開啟 http://localhost:3000。其他裝置需透過同一台伺服器的位址，例如同一個區域網路中的 `http://192.168.1.100:3000`（請換成主機實際 IP，並允許防火牆的 TCP 3000 連入）。若要讓不同網路的朋友加入，請部署到支援長連線及持久磁碟的 Node.js 主機，使用 HTTPS；請勿使用純靜態網頁主機。`PORT` 可調整連接埠，`DATA_DIR` 可指定持久存檔目錄。

例如在 PowerShell 指定連接埠與存檔位置：

```powershell
$env:PORT = '3000'
$env:DATA_DIR = 'C:\BingoData'
npm start
```

使用 Public IP 自行架設時，請將路由器的 TCP 連接埠轉送至執行程式的電腦，並允許對應防火牆連線。朋友應使用主機的公開網址，不能使用 `localhost`。

## 玩法

準備階段查看其他玩家的盤面時，畫面一律以「?」代替數字，不論對方是否已準備；自己的盤面仍可正常查看與編輯。開始遊戲後公開其他玩家的數字，重新開局回到準備階段時再次遮住。此為介面顯示規則。

遊戲介面使用木質外框、黑板盤面與粉筆標記。已覆蓋的格子顯示粉筆圈，完成橫線、直線或對角線時會畫出對應連線；切換玩家盤面及使用「上一步」時同步更新。房主的邀請與盤面設定可展開／收合，手牌維持抽屜操作。

每回合二選一：選一個號碼並抽一張卡，或使用一張卡。房主確認號碼後，伺服器從現有三種卡牌隨機發一張給選號者，加入正式手牌並換下一位；右側抽卡區固定顯示卡背，抽卡動畫結束後跳出視窗顯示卡片與效果；按「收下卡片」關閉，卡片已加入手牌，可從「我的手牌」使用。拒絕號碼不發卡、直接換人；使用卡牌不發卡，作答成功、失敗或房主取消後皆換人。發卡與確認號碼一起存檔，重送不重複發卡，上一步一併撤回。卡牌實際能力仍待設定。

### 連線獎品位置

盤面左側的獎品對應各條橫線，上方對應各條直線，左上角對應 ↘ 對角線，右上角對應 ↙ 對角線；所有尺寸的盤面單格與獎品圖框都維持目前 6×6 的格子大小；格數增加時擴大盤面，空間不足時可左右捲動。在相同畫面與遊戲階段中，切換格數不會縮放格子。取得的獎品會亮起並顯示勾選；已被其他玩家取得的格子會變灰並顯示叉號，將滑鼠移到圖示可查看得主。

獎勵池包含 `public/assets/items/` 中的突襲券、傳送石、飄雪結晶、護身符、`紅色藥水` 與 `活力藥水`。每局準備時由伺服器為每個獎品格獨立、等機率隨機抽選一種物品，允許重複，不保證每種都會出現。所有玩家共用同一份配置；本局的重連、重新整理、重新掃描與上一步不會重新抽選，已存在的存檔配置也會保留。房主可在開始前按「重新隨機獎品」重抽配置，所有玩家同步更新，盤面與準備狀態保持不變；正式開始時沿用最後一次顯示的配置，開始後無法重抽。**每個獎品格在全房只有一份**，由第一位完成該條線的玩家自動取得。同一次房主確認若有多人同時完成相同位置的連線，依加入順序決定得主。不同格可以配置相同道具，仍分別算一份；限量單位是獎品格，不是整種道具。

得主由伺服器在確認號碼時決定並存檔，待確認或被拒絕的號碼不會發獎，網路重送與重連也不會重複發放。遊戲結束後自動跳出「遊戲結束・獎勵結算」視窗，同種道具合併顯示數量，未取得獎品的玩家也會列出。關閉視窗後仍留在房間查看盤面，可按「查看獎勵結算」再次開啟；上一步或重新開局會關閉視窗。未被取得的獎品不會自動補發。

「上一步」會連同獎品得主與獲獎數量一起還原。重新開局、修改盤面尺寸會清空本局獲獎紀錄並補回全部獎品，請在重新開局前查看結算。既有房間升級時會依可用操作歷史重建先後得主；缺少的較早歷史只能依最早可用盤面與加入順序推定。實際遊戲帳號的道具發送、道具使用能力及房主自訂配置尚未實作。

房主可在準備階段使用「盤面尺寸」選擇 3×3 到 9×9（預設 5×5）。N×N 使用 1～N²，各數字一次，先完成（N − 2）條線獲勝。套用不同尺寸會同步重設所有玩家的盤面並取消準備；遊戲開始後需先重新開局才能改尺寸。尺寸會隨房間存檔，重連及重啟後保留；舊房間仍維持 5×5。

### 朋友專用連線頁

朋友可開啟 `http://你的Public-IP:3000/join`，輸入玩家 ID 與房號加入。房主建立房間後，可在「邀朋友入座」填入完整公開網址，例如 `http://你的Public-IP:3000`，按「儲存網址」後複製邀請。產生的 `/join?room=房號` 連結會自動帶入房號，朋友只要填玩家 ID。邀請區域只有房主可見；點擊房號只複製六碼房號，「複製邀請」才會複製完整連結。公開網址只保存在房主目前瀏覽器；清空欄位並儲存可恢復使用目前網站網址。這項設定只影響分享連結，路由器轉送與防火牆仍需事先開通。

1. 輸入玩家 ID 並建立房間，朋友使用不同玩家 ID 與相同房號加入，最多 16 人。
2. 在自己的盤面輸入畫面提示的數字範圍，每個數字使用一次，或按隨機排列。完成後按準備；準備後仍可取消準備修改。
3. 至少 2 人且全員準備後，房主可以開始。依加入順序輪流點擊自己盤面的未選號碼，房主會看到確認視窗（房主自己選號也需確認）。按「確認此號碼」後才同步標記、計算連線、發一張卡給選號者並換下一位；按「拒絕，換下一位」則不標記、不計分，直接換下一位，被拒絕的號碼仍可再次選擇。
4. 點擊玩家清單可查看他人的盤面，點自己的名字返回。伺服器只公開盤面及遊戲資訊，不公開玩家憑證。
5. 橫、直、兩條對角線皆可得分，N×N 先完成（N − 2）條線獲勝；同一個號碼可使多位玩家同時獲勝。房主可重新開局，原盤面保留、所有人重新準備。
6. 目前玩家離線時，先等待自動重連；房主也可按「略過目前離線玩家」。待確認期間所有玩家暫停選號，房主必須先確認或拒絕；房主離線時會等待其重連，確認視窗會自動恢復。待確認號碼一併存檔，伺服器重啟後仍可處理。房主身分固定保留，其他玩家無法代替房主確認或重新開局。

### 排名與通知

玩家清單依連線數由高到低排序，同分依加入順序。清單可上下捲動，並標示準備狀態、離線狀態及目前回合。排名不影響選號順序；回合始終依加入順序循環。

每次有玩家取得新獎品時，會顯示「XXX 獲得了 突襲券 × 1！」，同次取得多份會合併顯示。通知依實際獎品得主判定，不再顯示連線數，也不限定最高連線數；完成已被領走的獎品格不會跳通知。首次載入不重播既有獎品，重複同步不會重複通知；上一步撤回獎品後重新取得時可再次通知。

### 準備階段重新掃描玩家

玩家斷線時不會自動刪除資料，未掃描前仍可用同 ID 恢復。只有房主在準備階段按「重新掃描玩家」時，才會依目前伺服器的 SSE 連線狀態，直接刪除當時離線玩家的 ID 紀錄、盤面、手牌與準備狀態，並釋出名額。房主不會被刪除，仍在線的玩家保持原有盤面與準備狀態。畫面顯示在線／總人數及本次刪除人數；掃描後仍需至少 2 位玩家且全部準備，才能開局。

掃描刪除後不再封存或恢復該玩家的舊資料；若使用相同 ID 再加入，視為新玩家，需重新排列盤面及準備，手牌為空。已刪除的憑證不能自動恢復連線；遊戲開始後須等下一局才能重新加入。舊版的 `archivedPlayers` 封存資料也會在按下掃描時清除。掃描使用伺服器已知的連線狀態，突然斷網的判定可能延遲；正常關閉頁面通常會立即更新。同 ID 若仍有其他分頁在線，不會被刪除。

## 遊戲選擇

房主在建立房間前可選擇「Bingo」或「Bridge Bingo」，預設 Bingo。Bridge Bingo 使用獨立的 `/bridge-bingo?room=房號` 頁面，已實作分隊、共同盤面與三色配牌、私人手牌、跟色／自由牌、隊伍由上到下依序出牌、同步輪次與同輪平手。玩法與操作見 [橋牌賓果說明](docs/bridge-bingo.md)。房間會保存遊戲種類，加入與重連時自動顯示對應頁面；舊房間預設維持 Bingo，加入者無法更改房間遊戲種類。

## 格子狀態與手牌基礎

每位玩家都有獨立的 `cells`，每格格式為 `{ number: 1, isCovered: false }`。`isCovered` 控制是否蓋住（標記），連線判定直接使用這個布林值；房主確認號碼後才會蓋住，之後可擴充成只影響特定玩家或特定格子的功能。舊存檔會從已選號碼初始化格子，已有合法狀態則完整保留。

每位玩家都有獨立 `hand` 陣列，正式手牌初始為空，確認選號後從目前三種卡牌隨機抽一張加入手牌，每張有獨立 ID，可重複抽到同種類。使用時從手牌移除並公開題目，由房主判定；數量上限與實際能力尚未設定。伺服器已提供新增／移除正式手牌的內部函式；其他玩家只看到正式手牌張數，只有本人可收到完整內容。手牌與格子狀態會存檔，重連與上一步可恢復；重新開局及更改尺寸會清空正式手牌與覆蓋狀態。

目前另提供三張示範卡體驗操作，消耗紀錄保存在 `usedDemoCards`，不放入正式 `hand`。抽屜上方的張數計算畫面內的正式手牌與剩餘示範卡總數；玩家清單的手牌張數只計算正式手牌。因此初始抽屜顯示 3 張、清單顯示 0 張是兩者計算範圍不同。

## 卡牌同步作答

底部固定顯示「我的手牌」入口，點開才展開抽屜，不會增加遊戲頁面的長度。卡牌可橫向捲動，點「收起」、抽屜外側空白處或按 Esc 可關閉抽屜。

1. **點選卡牌即使用**：消耗該張示範卡，全房立即看到使用者、卡名、效果說明、題目與選項。
2. **使用者作答**：只有用牌者能選擇並提交答案，其他玩家可觀看。此時遊戲暫停。
3. **房主判定**：提交後鎖定答案，由房主按「回答正確」或「回答錯誤」。系統不自動比對預設答案；若房主自己用牌，也由房主判定。
4. **全房公布結果**：以放大文字顯示「回答正確！」或「回答錯誤」，卡牌效果與題目仍可查看。
5. **結束回合**：由使用者或房主按「結束回合，換下一位」，所有人同步關閉視窗並換人。

遊戲中的每回合只能**選號或用牌，二擇一**。用牌後不論答對、答錯，或由房主中止，都不能再選號或使用另一張卡，結束後換下一位。回合只推進一次，網路重送不會重複消耗卡牌或多跳一位。

作答、等待判定與結果展示期間，暫停選號、號碼確認、略過、上一步、重新開局及其他遊戲操作。房主可隨時按「結束作答」，讓離線或無法繼續回答的玩家結束本回合；中止也會消耗卡牌。重新整理、重連及伺服器重啟會恢復目前的題目、已提交答案或判定結果。

目前三張示範卡為「星光指引」、「森林守護」、「月影之謎」，能力顯示「能力待定」，不改動盤面或正式手牌。準備階段也能體驗，但不推進回合；遊戲中限自己的回合、尚無待確認號碼時使用。重新開局或更改盤面尺寸會補回示範卡。

遊戲中的一次卡牌使用（含作答、判定與結束）視為一個撤回步驟。完成後按「上一步」，會還原卡牌與用牌前的回合。

## 重連與存檔

房主可在盤面下方或待確認視窗按「上一步」，一路退回本局剛開始：清空已選號碼、連線成績與待確認號碼，由第一位玩家選號，保留所有玩家的盤面與準備狀態。例如撤回「確認」會取消標記與成績並回到待確認視窗，再按一次則撤回該次選號。勝出後也可撤回最後的確認，恢復遊戲。更新前沒有完整紀錄的較早部分，最後一步會直接回到開局狀態，無法重建當時每次拒絕或略過的順序。重新開局會清除本局撤回紀錄；紀錄會存檔並在伺服器重啟後保留。

- 使用 SSE 同步，15 秒心跳，自動重連後取得完整最新狀態。短暫斷線期間停用選號，恢復後重新同步。
- 以「房號＋玩家 ID」辨認玩家，原暱稱欄位現在是玩家 ID。相同房間輸入完全相同的 ID（區分大小寫）即可恢復原盤面、準備狀態及房主身分，遊戲開始後也能恢復；不同 ID 為不同玩家。這是免密碼的房間身分識別，知道同一 ID 就能使用該身分，並非具密碼保護的帳號登入。
- 每個分頁用 sessionStorage 記住正在使用的 ID 與憑證，重新整理、短暫斷線會自動恢復；不同無痕視窗可輸入不同 ID。點頁尾「切換玩家 ID」可重新輸入。同瀏覽器的「複製分頁」可能複製原分頁資料，這時可用此按鈕切換。升級時第一個重新整理的分頁會接手舊的共用身分；其他分頁請輸入各自 ID。
- 操作遇到網路問題最多自動重試 4 次，每次沿用相同操作 ID，伺服器去重，避免重複選號。超出次數會顯示錯誤；可重連後查看最新狀態。
- 每個成功操作同步寫入 `data/rooms.json`，以暫存檔替換。重啟伺服器後保留房間、盤面、已選號碼、回合及身分。未按準備的編輯內容只是本地草稿，重新整理不保留。
- 關閉分頁、清除瀏覽器資料或換裝置後，可重新輸入原房號與玩家 ID 恢復身分；需保留伺服器存檔。公開邀請網址仍儲存在共用 localStorage。
- 本版本為單一 Node.js 程序，房間不自動過期，最多 1,000 房。正式大量使用時需改用資料庫、房間清理與跨程序同步；請勿同時啟動多個程序共用存檔。玩家 ID 為免密碼識別，不是具密碼保護的帳號系統。

| `test/client-modules.test.js` | 前端快照、草稿、分頁身分、API 重試、獎品取得通知、各尺寸粉筆連線位置及逐線獎品狀態 |
| `test/card-ui.test.js` | 手牌數量、抽屜、全房卡牌展示、房主判定控制及結果文字切換 |
| `test/shared-cards.test.js` | 作答與判定權限、暫停、重送去重、用牌後換人及整次用牌撤回 |
| `test/line-prizes.test.js` | 獎品獨占、同時連線順序、重送去重、結算、撤回、舊歷史遷移與存檔重啟 |

介面單元測試使用模擬 DOM，驗證狀態與操作邏輯；視窗排版、捲軸、字體大小及按鈕是否被遮住，仍需在瀏覽器中檢查。

使用卡牌後，在尚未提交答案前，可由使用者點擊視窗外側、右上角「×」或 Esc 取消。卡片退回、保留回合，所有玩家同步關閉作答視窗；提交答案後不能退卡。房主的「結束作答」仍屬原有略過回合操作，會消耗卡片並換人。

首頁 `/` 不會自動加入上次房間，會顯示建立／加入表單；重新整理帶有 `?room=房號` 的遊戲連結時，才會自動恢復相同房間。按「建立新房間」會產生新房號，不沿用舊局進度；舊房間保留。

單獨執行 Bridge Bingo 核心單元測試：`npm run test:unit:bridge`。這組測試不啟動 HTTP 服務、不讀寫遊戲存檔；完整回歸測試仍使用 `npm test`。

遊戲程式分別放在 `src/games/bingo`、`src/games/bridge` 與 `public/js/games/` 對應目錄，透過共用 registry 接到房間服務與應用程式。共用邊界與新增遊戲方式見 [架構與物件關係](docs/architecture.md)，可執行 `npm run test:architecture` 驗證隔離。

## BingoNext

首頁新增獨立遊戲 **BingoNext**：隊伍共用一張盤面，選號立即佔領並抽卡，不需房主確認；只有整條線屬於同隊才能獲得隊伍獎品。達到邊長 − 2 條線獲勝，盤面滿時按連線數結算。原版 Bingo 與 Bridge Bingo 保留。玩法與平衡待討論項目見 [BingoNext 說明](docs/bingo-next.md)。
